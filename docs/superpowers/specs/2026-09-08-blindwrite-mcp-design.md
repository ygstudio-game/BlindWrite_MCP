- **Date:** 2026-09-08
- **Author:** Antigravity Pair Architecture Agent

- **Model Gateway:** OpenRouter API
- **Persistence:** SQLite (Node.js LTS / better-sqlite3 with WAL mode)

## 1. Executive Summary & Problem Statement

### 1.1 The Problem
Public AI benchmarks (e.g. Chatbot Arena, MMLU, AlpacaEval) measure generic reasoning or coding capability. They fail to answer the critical question for professional writers, marketers, and knowledge workers:
> **"Which AI model writes best for *me*, my personal voice, and my specific writing domains?"**

Furthermore, evaluation is plagued by **brand bias**: when users know an output was generated by a premier brand (e.g., "OpenAI GPT-4o" or "Anthropic Claude 3.5 Sonnet"), their subjective perception is skewed.

### 1.2 The Solution: BlindWrite MCP
BlindWrite MCP is an enterprise-grade Model Context Protocol (MCP) server that transforms Claude Desktop into a blind AI evaluation arena:
1. The user requests a writing benchmark (e.g., *"Benchmark the best models for executive summary emails"*).
2. Claude uses BlindWrite MCP to dispatch the identical prompt to competing frontier models via OpenRouter in parallel.
3. BlindWrite strips all branding, provider metadata, and model identities, storing raw outputs securely in a local SQLite database and assigning cryptographically random anonymous identifiers.
4. Claude orchestrates randomized, position-balanced A/B duels (`Response A` vs `Response B`).
5. The user votes on preferred responses with optional dimension scores (`clarity`, `tone`, `conciseness`, `structure`) and reasoning.
6. A mathematical ranking engine computes **Bradley-Terry Maximum Likelihood Estimates (MLE)** with uncertainty/confidence intervals alongside dynamic **Elo** ratings.
7. Upon concluding the tournament, a reveal stage unmasks the models, providing personal leaderboards, cost-vs-quality comparisons, and deep preference analytics explaining *why* specific models outperform others for that user.

| Dependency | Purpose | Rationale |
|---|---|---|
| `@modelcontextprotocol/sdk` | MCP Server & stdio transport | Official standard MCP implementation |
| `typescript` (~5.7+) | Type safety | Strict compile-time safety (`strict: true`) |
| `better-sqlite3` | SQLite engine | Synchronous, zero-latency local queries with native speed |
| `zod` (~3.24+) | Schema validation | Runtime validation for MCP tool arguments & environment |
| `dotenv` | Environment management | Safe API key loading from `.env` |
| `vitest` | Test framework | Fast ESM-native unit & integration test runner |

### Stdio Communication Hygiene
Standard output (`stdout`) is strictly reserved for the MCP JSON-RPC protocol. Any arbitrary `console.log()` corrupts the transport and crashes Claude Desktop.
* **Rule:** All application logging, debug output, and error traces must use a dedicated logger writing exclusively to `console.error` (`stderr`).

## 4. Database Schema (SQLite)

The database uses SQLite with Foreign Keys enabled and WAL (Write-Ahead Logging) mode.

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

-- Users table (supports multi-user / session isolation)
CREATE TABLE IF NOT EXISTS users (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Models catalog
CREATE TABLE IF NOT EXISTS models (
    id TEXT PRIMARY KEY,                       -- e.g. "claude-3-5-sonnet"
    openrouter_model_id TEXT UNIQUE NOT NULL,  -- e.g. "anthropic/claude-3.5-sonnet"
    display_name TEXT NOT NULL,                -- e.g. "Claude 3.5 Sonnet"
    provider TEXT NOT NULL,                    -- e.g. "Anthropic"
    enabled INTEGER NOT NULL DEFAULT 1,
    prompt_price_per_m REAL DEFAULT 0.0,       -- USD per million prompt tokens
    completion_price_per_m REAL DEFAULT 0.0,   -- USD per million completion tokens
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Benchmark tasks
CREATE TABLE IF NOT EXISTS benchmark_tasks (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL REFERENCES users(id),
    title TEXT NOT NULL,
    category TEXT NOT NULL,                    -- e.g. "Emails", "Technical Writing"
    prompt TEXT NOT NULL,
    evaluation_criteria TEXT,
    difficulty TEXT DEFAULT 'medium',
    status TEXT NOT NULL DEFAULT 'created',    -- 'created', 'generating', 'ready', 'completed'
    revealed INTEGER NOT NULL DEFAULT 0,       -- 0 = models hidden; 1 = revealed
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Model outputs for benchmark tasks
CREATE TABLE IF NOT EXISTS benchmark_outputs (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL REFERENCES benchmark_tasks(id) ON DELETE CASCADE,
    model_id TEXT NOT NULL REFERENCES models(id),
    anonymous_id TEXT NOT NULL,                -- Masked ID exposed during battles
    output_text TEXT NOT NULL,
    prompt_tokens INTEGER DEFAULT 0,
    completion_tokens INTEGER DEFAULT 0,
    total_tokens INTEGER DEFAULT 0,
    latency_ms INTEGER DEFAULT 0,
    estimated_cost REAL DEFAULT 0.0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Pairwise battles
CREATE TABLE IF NOT EXISTS battles (
    id TEXT PRIMARY KEY,
    task_id TEXT NOT NULL REFERENCES benchmark_tasks(id) ON DELETE CASCADE,
    output_a_id TEXT NOT NULL REFERENCES benchmark_outputs(id),
    output_b_id TEXT NOT NULL REFERENCES benchmark_outputs(id),
    status TEXT NOT NULL DEFAULT 'pending',    -- 'pending', 'voted'
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- User votes
CREATE TABLE IF NOT EXISTS votes (
    id TEXT PRIMARY KEY,
    battle_id TEXT NOT NULL REFERENCES battles(id) ON DELETE CASCADE,
    user_id TEXT NOT NULL REFERENCES users(id),
    selected_output_id TEXT REFERENCES benchmark_outputs(id), -- NULL on tie
    is_tie INTEGER NOT NULL DEFAULT 0,
    reason TEXT,
    dimension_scores TEXT,                     -- JSON: {"clarity": 5, "tone": 4}
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Aggregated rankings cache
CREATE TABLE IF NOT EXISTS rankings (
    id TEXT PRIMARY KEY,
    scope TEXT NOT NULL,                       -- 'personal' or 'global'
    user_id TEXT,                              -- NULL for global
    category TEXT,                             -- NULL for overall, or specific category
    model_id TEXT NOT NULL REFERENCES models(id),
    bradley_terry_score REAL NOT NULL DEFAULT 100.0,
    elo_rating REAL NOT NULL DEFAULT 1200.0,
    battles_count INTEGER NOT NULL DEFAULT 0,
    wins_count INTEGER NOT NULL DEFAULT 0,
    losses_count INTEGER NOT NULL DEFAULT 0,
    ties_count INTEGER NOT NULL DEFAULT 0,
    win_rate REAL NOT NULL DEFAULT 0.0,
    uncertainty REAL NOT NULL DEFAULT 1.0,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_tasks_user ON benchmark_tasks(user_id);
CREATE INDEX IF NOT EXISTS idx_outputs_task ON benchmark_outputs(task_id);
CREATE INDEX IF NOT EXISTS idx_battles_task ON battles(task_id);
CREATE INDEX IF NOT EXISTS idx_votes_battle ON votes(battle_id);
CREATE INDEX IF NOT EXISTS idx_rankings_lookup ON rankings(scope, category, model_id);
```

## 6. MCP Tool Specifications

### 6.1 `benchmark_create_task`
* **Purpose:** Creates a benchmark task for a specific writing category.
* **Input Schema:**
  ```typescript
  {
    title: z.string().min(3).max(120),
    category: z.string(),
    prompt: z.string().min(10),
    evaluation_criteria?: z.string().optional(),
    difficulty?: z.enum(["easy", "medium", "hard"]).optional().default("medium"),
    user_id?: z.string().optional().default("default_user")
  }
  ```
* **Output:**
  ```json
  {
    "task_id": "tsk_01jk4...",
    "title": "Executive Cold Email",
    "category": "Emails",
    "status": "created",
    "created_at": "2026-09-08T13:00:00.000Z"
  }
  ```

### 6.2 `benchmark_list_models`
* **Purpose:** Lists available models in the registry.
* **Input Schema:**
  ```typescript
  {
    category?: z.string().optional(),
    enabled_only?: z.boolean().optional().default(true)
  }
  ```
* **Output:** Array of models with display names, providers, and pricing.

### 6.3 `benchmark_generate_outputs`
* **Purpose:** Triggers parallel prompt generation across selected models via OpenRouter.
* **Input Schema:**
  ```typescript
  {
    task_id: z.string(),
    model_ids?: z.array(z.string()).optional(), // Defaults to all enabled
    temperature?: z.number().min(0).max(2).optional().default(0.7)
  }
  ```
* **Output:**
  ```json
  {
    "task_id": "tsk_01jk4...",
    "models_dispatched": 5,
    "outputs_generated": 5,
    "total_cost_estimate_usd": 0.0084,
    "status": "ready",
    "anonymous_output_ids": ["anon_3b8a", "anon_9f21", "anon_1c44", "anon_7e8b", "anon_5d10"]
  }
  ```
* **Blindness Guarantee:** Under no circumstances are model identities or provider strings returned.

### 6.4 `benchmark_start_duel`
* **Purpose:** Sets up an A/B duel from generated outputs, balancing positions randomly.
* **Input Schema:**
  ```typescript
  {
    task_id: z.string(),
    output_a_id?: z.string().optional(),
    output_b_id?: z.string().optional()
  }
  ```
* **Output:**
  ```json
  {
    "battle_id": "btl_01jk4...",
    "task_id": "tsk_01jk4...",
    "prompt": "...",
    "evaluation_criteria": "...",
    "response_a": {
      "id": "anon_3b8a",
      "text": "..."
    },
    "response_b": {
      "id": "anon_9f21",
      "text": "..."
    },
    "voting_instructions": "Review Response A and Response B. Submit your vote with 'A', 'B', or 'tie', and optional feedback."
  }
  ```
* **Anti-Bias Protocol:** A 50/50 cryptographic coin toss determines whether output 1 becomes A or B.

### 6.5 `benchmark_submit_vote`
* **Purpose:** Records the user's vote for a battle.
* **Input Schema:**
  ```typescript
  {
    battle_id: z.string(),
    choice: z.enum(["A", "B", "tie"]),
    reason?: z.string().optional(),
    dimension_scores?: z.record(z.string(), z.number().min(1).max(5)).optional()
  }
  ```
* **Output:**
  ```json
  {
    "vote_id": "vot_01jk4...",
    "battle_id": "btl_01jk4...",
    "status": "recorded",
    "unbattled_pairs_remaining": 3
  }
  ```

### 6.6 `benchmark_get_results`
* **Purpose:** Fetches results for a benchmark task.
* **Input Schema:**
  ```typescript
  {
    task_id: z.string(),
    reveal?: z.boolean().optional().default(false)
  }
  ```
* **Output (when `reveal: true`):**
  Sets `revealed = 1` in the database and returns unmasked model identities, win rates, latencies, and token costs.

### 6.7 `benchmark_get_leaderboard`
* **Purpose:** Retrieves the personal or global leaderboard.
* **Input Schema:**
  ```typescript
  {
    scope?: z.enum(["personal", "global"]).optional().default("personal"),
    category?: z.string().optional(),
    metric?: z.enum(["bradley_terry", "elo", "win_rate"]).optional().default("bradley_terry"),
    min_battles?: z.number().optional().default(1)
  }
  ```

### 6.8 `benchmark_compare_models`
* **Purpose:** Direct head-to-head comparison between two models.
* **Input Schema:**
  ```typescript
  {
    model_a_id: z.string(),
    model_b_id: z.string(),
    category?: z.string().optional()
  }
  ```

### 6.9 `benchmark_analyze_preferences`
* **Purpose:** Discovers empirical writing style preferences from voting history.
* **Input Schema:**
  ```typescript
  {
    category?: z.string().optional(),
    min_votes?: z.number().optional().default(3)
  }
  ```

### 6.10 `benchmark_get_model_stats`
* **Purpose:** Deep statistical profile of a single model.
* **Input Schema:**
  ```typescript
  {
    model_id: z.string()
  }
  ```

## 7. Ranking Engine & Mathematics

### 7.1 Bradley-Terry Maximum Likelihood Estimation (MLE)
The probability that model $i$ beats model $j$ is given by:
$$P(i \succ j) = \frac{\pi_i}{\pi_i + \pi_j} = \frac{e^{\beta_i}}{e^{\beta_i} + e^{\beta_j}}$$
where $\beta_i = \ln(\pi_i)$.

We solve for $\pi$ using the iterative Minorization-Maximization (MM / Hunter 2004) algorithm:
$$\pi_i^{(t+1)} = \frac{W_i + \alpha}{\sum_{j \ne i} \frac{N_{ij}}{\pi_i^{(t)} + \pi_j^{(t)}} + \alpha}$$
* $W_i$: Total wins for model $i$ (ties count as $0.5$).
* $N_{ij}$: Total matchups between model $i$ and $j$.
* $\alpha = 1.0$: Laplace prior regularizer ensuring numerical stability and handling disconnected graphs.
* Convergence: Stop when $\max_i |\pi_i^{(t+1)} - \pi_i^{(t)}| < 10^{-5}$.
* Scaling: Standardize scores to a baseline of 100.0.

### 7.2 Uncertainty & Confidence Intervals
Standard errors are computed from the inverse observed Fisher Information matrix:
$$SE(\hat{\beta}_i) = \sqrt{[I(\hat{\beta})]^{-1}_{ii}}$$
Uncertainty levels presented to the user:
* **High Uncertainty (Preliminary):** $< 5$ battles.
* **Moderate Uncertainty (Emerging):** $5–15$ battles.
* **High Confidence (Established):** $> 15$ battles.

### 7.3 Elo Rating System
$$R_{new} = R_{old} + K \cdot (S - E)$$
* Base rating: $1200$.
* $K = 32$ for $< 20$ battles; $K = 16$ thereafter.

## 8. Testing & Verification Plan

### 8.1 Unit Tests (`tests/unit/`)
* **Bradley-Terry Math:** Verify convergence with known synthetic pairwise matrices; test tie handling and regularization stability with $0$ wins.
* **Elo Calculations:** Verify rating changes across win/loss/tie outcomes.
* **Randomization & Blindness:** Verify uniform distribution of A/B assignments over 1,000 iterations to ensure zero positional bias.
* **Preference Analytics:** Verify correlation logic on mock vote histories.

### 8.2 Integration Tests (`tests/integration/`)
* **End-to-End Benchmark Workflow:**
  1. Create task.
  2. Mock OpenRouter response generation.
  3. Start duel (verify anonymous masking).
  4. Submit vote.
  5. Verify results reveal gating (`reveal: false` hides models; `reveal: true` unmasks).
  6. Verify leaderboard update and category isolation.
